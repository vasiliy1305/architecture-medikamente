| Класс данных      | Зачем защищать                     | Инструменты защиты                                                             |
| ----------------- | ---------------------------------- | ------------------------------------------------------------------------------ |
| **MEDICAL**       | Это чувствительные медицинские данные, их утечка может привести к серьёзным последствиям и штрафам | Шифрование БД (AES-256, TDE), шифрование бэкапов, TLS 1.3 при передаче, mTLS между сервисами, контроль доступа (RBAC), логирование |
| **PERSONAL DATA** | Персональные данные пользователей требуют защиты по закону| Шифрование хранилища, TLS при передаче, хранение секретов в Vault, контроль доступа   |
| **FINANCIAL DATA**| Риск финансовых потерь и мошенничества    | TLS, шифрование БД, токенизация, хранение ключей в защищённом хранилище  |
| **ANONYMIZED**    | Хотя данные обезличены, возможна повторная идентификация  | TLS, ограничение доступа, контроль выгрузок      |
| **SECRETS** (пароли, токены) | Компрометация может дать доступ ко всей системе   | Hashing (bcrypt/argon2), Vault, ротация ключей, TLS      |
| **LOGS**          | В логах может быть техническая и чувствительная информация    | Шифрование хранилища логов, TLS, контроль доступа    |
| **PUBLIC DATA**   | Нужно обеспечить целостность и защиту от атак        | HTTPS |
